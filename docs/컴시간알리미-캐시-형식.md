# 컴시간알리미 로컬 캐시 형식

컴시간알리미2(2026.00.0017)가 교내 서버에서 받아 `C:\Program Files (x86)\알림이\dat\tmp\`에 저장하는 파일을 분석한 결과입니다. 비공식 분석이며 알리미가 업데이트되면 달라질 수 있습니다. 파일은 읽기만 합니다.

## 공통 규칙

- 텍스트는 CP949, 숫자는 리틀 엔디언입니다. 암호화·압축은 없습니다.
- **격자 레코드**: 252바이트 = int32 × 63. 칸 위치는 `요일 + 7 × 교시`입니다(요일 0~6, 1=월 … 5=금 / 교시 0~8, 1교시=1). 0은 수업 없음입니다.
- 번호는 모두 1부터 시작합니다(교사, 과목, 학년, 반, 주).
- 알리미가 약 20분마다 `dayhour*.kim`, `주간일자.kim`, `cfg*.kim`을 지웠다가 다시 씁니다. 그 순간에는 파일이 없거나 덜 쓰여 있으므로, 읽기 실패 시 재시도하고 크기가 맞을 때만 반영해야 합니다.

## 값의 의미

| 값이 있는 곳 | 해석 |
|---|---|
| 교사 격자 | `과목 × 1000 + 학년 × 100 + 반` (예: 61210 → 과목 61, 2학년 10반) |
| 학급 격자 | `과목 × 1000 + 교사` (예: 24031 → 과목 24, 교사 31) |
| 학급 원래자리 격자 | `월 × 1000 + 일 × 10 + 교시` (예: 11122 → 11월 12일 2교시) |

원래자리 값이 그 칸의 날짜·교시와 다르면 옮겨 온 수업입니다.

## 파일별 구조

| 파일 | 구조 |
|---|---|
| `교사명.kim` | `^이름^이름…` 순서가 교사 번호 |
| `과목명.kim` | `$전체이름^줄임말$…` 순서가 과목 번호 |
| `교과교실명.kim` | `코드,이름,^…` |
| `기본교사시간표.kim` | 격자 레코드. 레코드 번호 = 교사 − 1 |
| `기본학급시간표.kim` | 격자 레코드. 레코드 번호 = (학년 − 1) × 30 + 반 − 1 |
| `주간일자.kim` | 1452바이트 레코드. int16 주 번호, double 월요일 날짜(OLE 날짜), 이어서 int16 배열 `[학년 + 4 × 요일]` = 그날 교시 수(0이면 휴업) |
| `dayhour_t.kim` | 주차별 교사 시간표. 레코드 번호 = (주 − 1) × 400 + (교사 − 1) × 2. 바로 다음 레코드는 비어 있음 |
| `dayhour.kim` | 주차별 학급 시간표. 레코드 번호 = ((주 − 1) × 3 + 학년 − 1) × 60 + (반 − 1) × 2. 바로 다음 레코드가 원래자리 격자 |
| `cfg2.kim` | `저장일=…` 마지막 수신 시각 |

## 교사 시간표 만들기

1. `주간일자.kim`에서 날짜가 속한 주 번호와 월요일 날짜를 찾습니다.
2. `dayhour_t.kim`에서 그 주·교사의 격자를 읽습니다. 범위를 벗어나면 빈 격자로 봅니다.
3. 칸마다 과목·학년·반으로 풀고, `과목명.kim`의 줄임말을 붙입니다.
4. 변경 표시: 해당 학급의 원래자리 격자(`dayhour.kim`)가 다른 날짜·교시를 가리키면 "옮겨 온 수업", 기본 시간표에는 있는데 그 주에 0이면 "빠진 수업"입니다.

## 검증

- 기본 시간표: 학급표의 모든 칸(900개)이 교사표의 같은 칸과 일치했습니다.
- 주차별: 자료가 있는 20개 주의 모든 칸(주당 150~990개)이 학급표와 교사표 사이에서 일치했습니다.
- 알리미가 레지스트리에 남긴 본인 변경 기록(`컴시간\Settings\변경시간표`)과 11월 23일 주의 추출 결과가 일치했습니다.

## 해독하지 않은 것

`dayhour_sb.kim`·`sbClass.kim`(선택과목 묶음으로 추정), `dongsi.kim`(동시수업), `spsil.kim`(특별실 배정), `cfg.kim`(학교 설정), `변경요청함`, `공지사항`. 교실 표시가 필요하면 `spsil.kim`을 추가로 분석해야 합니다.
