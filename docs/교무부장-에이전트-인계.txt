학교 학사일정 서버 구축 — 에이전트 인계

이 문서와 서버 템플릿 ZIP, 기존 학사일정 HTML을 에이전트에게 함께 전달하세요.
계정 로그인과 필요한 소유자 승인 절차는 담당자가 직접 진행합니다.

[에이전트에게 요청할 내용]

첨부한 SchoolCalendar-Server-Template-1.0.0.zip을 사용해 우리 학교의 학사일정 서버를 구축해 주세요.
Windows 바탕화면 앱 2.2.0은 이미 완성되어 있습니다. 앱을 새로 만들 필요는 없습니다.
목표는 담당자가 관리자 웹에서 일정을 수정·게시하면, 연결한 PC 달력에 자동 반영되도록 하는 것입니다.

1. 운영 주체와 자료
- 우리 학교 담당자가 소유한 Git 저장소·Vercel·Supabase 계정을 사용합니다.
- 앱 제작자의 계정이나 중앙 서버에 의존하지 않는 독립 배포입니다.
- 제작자의 GitHub 저장소는 비공개일 수 있습니다. 접근할 수 없다면 첨부 ZIP을 그대로 사용하세요.
- ZIP 안의 README.md를 먼저 읽고 PROTOCOL.md, setup.sql, .env.example을 확인하세요.
- 기존 학사일정 HTML은 초기 일정 데이터입니다. 관리자 웹에 가져오기 기능이 있습니다.
- 공통 설치 파일: SchoolScheduler-2.2.0-x64-Setup.exe.

2. 시작 전 담당자에게 확인할 사항
- 사용할 학교 이름과 운영 계정.
- 학교 일정의 공개 조회가 가능한지, 교직원에게 안내하는 읽기 토큰이 필요한지.
- 초기 일정으로 사용할 HTML 파일이 최신본인지.
- 유료 서비스나 추가 비용이 필요하면 담당자 승인을 먼저 받으세요.

3. Supabase 구성
- 학교용 전용 프로젝트를 사용하고 기존의 다른 업무용 테이블은 변경하지 마세요.
- 새 프로젝트에 setup.sql을 한 번 실행하세요. 이미 설치되어 있다면 재실행하지 말고 현재 상태를 확인하세요.
- 담당자의 관리자 계정을 만들고, README의 절차대로 해당 계정의 app_metadata.calendar_admin=true 권한을 부여하세요.
- user_metadata를 관리자 권한 판단에 사용하지 마세요.
- RLS와 테이블 접근 권한을 유지하고 일반 사용자가 초안·게시 이력에 접근하지 못하는지 확인하세요.

4. Vercel 배포
- ZIP의 schedule-server 폴더를 본인 Git 저장소에 올려 배포하세요.
- 폴더 자체가 저장소 루트라면 Root Directory는 기본값입니다. 상위 폴더째 올렸다면 schedule-server를 지정하세요.
- 템플릿 기준 Node.js 24.x, Framework Other, npm run build, Output Directory public입니다. 배포 시 지원 여부와 동작을 확인하세요.
- .env.example을 참고해 다음 서버 환경 변수를 설정하세요.
  SUPABASE_URL
  SUPABASE_PUBLISHABLE_KEY
  SUPABASE_SECRET_KEY
  SCHEDULE_READ_TOKEN (읽기 제한이 필요한 경우 임의의 32자 이상 값)
- 서버 비밀 키·관리자 비밀번호는 Git·클라이언트 코드·일정 연결 주소·작업 보고서에 넣지 마세요.
- 읽기 토큰은 공유용 읽기 암호입니다. 개인별 교직원 로그인이나 개별 권한 회수 기능은 아닙니다.
- 앱이 접근할 수 있는 최종 Production HTTPS 주소를 사용하세요. Vercel 로그인 화면이나 리디렉션 주소를 일정 주소로 안내하지 마세요.

5. 초기 일정 등록
- 배포한 관리자 웹에 담당자 계정으로 로그인하세요.
- 달력 이름을 설정하고 기존 학사일정 HTML을 가져오세요.
- 가져온 일정 수·기간·제목을 원본과 대조한 뒤 초안을 저장하고 전체 일정을 게시하세요.
- HTML 스크립트는 실행하지 마세요. 템플릿의 가져오기는 EVENTS JSON 배열만 읽습니다.

6. 실제 동작 검증
- npm ci, npm test, npm run build를 실행하고 결과를 확인하세요.
- 실제 배포한 /api/calendar가 HTML이 아닌 공통 규격 v1 JSON을 반환하는지 확인하세요.
- 첫 게시 전 404는 정상입니다. 첫 게시 후에는 유효한 일정이 반환되어야 합니다.
- 읽기 토큰을 설정했다면 토큰 없는 조회가 401이고, 올바른 토큰으로 조회하면 성공해야 합니다.
- 일반 로그인 계정으로 관리자 작업이 거부되는지 확인하세요.
- 담당자 PC의 데스크톱 앱에서 '학교 일정 연결'에 최종 주소와 필요한 읽기 토큰을 입력해 실제로 연결하세요.
- 시험 일정의 추가·수정·삭제가 게시 후 앱에 반영되는지 확인하세요. 초안 저장만으로는 반영되지 않아야 합니다.
- 게시 이력에서 이전 내용을 초안으로 가져와 다시 게시하는 복원 절차도 확인하세요.
- 실제 운영 일정을 최종 상태로 남기고 시험 자료는 정리하세요.
- 개인 메모·개인 일정·할 일은 PC에 저장되는 기존 구조를 유지하세요. 서버로 올리는 기능은 추가하지 마세요.

7. 완료 후 담당자에게 전달할 결과
- 관리자 웹 주소: https://학교서버주소/
- 선생님들 앱에 입력할 일정 연결 주소: https://학교서버주소/api/calendar
- 읽기 토큰 사용 여부와, 사용하는 경우 담당자가 안전하게 보관·안내할 방법.
- 우리 학교 소유의 저장소와 Vercel·Supabase 프로젝트 위치.
- 실제 앱 연결 및 수정·삭제 반영 검사 결과.
- 담당자가 이후 사용할 짧은 운영 안내: 로그인 → 수정 → 초안 저장 → 확인 → 전체 일정 게시.

[선생님들께 안내할 문구]

1. 전달받은 학사일정 스케줄러 설치 파일을 실행해 설치하세요.
2. 달력의 할 일 패널 아래 '학교 일정 연결'을 누르세요.
3. 학교에서 안내한 일정 연결 주소를 붙여 넣으세요.
4. 읽기 토큰을 안내받았다면 함께 입력하고 '확인 후 연결'을 누르세요.
5. 이후 학교 일정은 앱 시작 시와 5분마다 자동 갱신됩니다.
6. 개인 메모와 할 일은 본인 PC에만 저장됩니다.
