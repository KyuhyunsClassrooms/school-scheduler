# 2.2 성능 개선과 측정

측정일: 2026-10-25. 2.1.0 소스와 개선 소스를 같은 PC, 같은 **1885×1616** 달력 크기, 같은 127개 학교 일정으로 비교했습니다. 논리 프로세서 수는 12개이며 실제 Explorer 합성을 활성화한 Windows 네이티브 앱입니다.

## 변경한 부분

- 달력 비트맵을 재사용하고, 날짜 hover는 이전·현재 날짜 테두리만 갱신합니다.
- 매 프레임 할당하던 전체 픽셀 배열과 이전 프레임 사본을 제거했습니다. Bitmap에서 공유 메모리로 변경 영역을 직접 복사합니다.
- 창을 이동할 때 좌표만 전송하며, 크기와 내용이 같으면 픽셀을 다시 만들거나 복사하지 않습니다.
- Explorer도 변경 영역만 받아 복사하고, 화면 전체 대신 실제 손상 영역 크기의 합성 버퍼를 재사용합니다. 큰 임시 버퍼가 불필요해지면 줄입니다.
- 공유 섹션의 최대 주소 공간은 64MiB로 유지하되 `SEC_RESERVE`와 `VirtualAlloc(MEM_COMMIT)`으로 실제 프레임에 필요한 페이지만 할당합니다. 이 크기의 프레임은 약 12MiB입니다. 실제 사용량과 가상 주소 예약은 다릅니다.
- 숨은 호스트 창의 이중 버퍼를 끄고, 숨긴 달력의 변경은 다시 표시할 때 그립니다. 일반 창 모드는 이중 버퍼를 유지합니다.
- 월간 일정과 할 일 조회 결과를 캐시하고 데이터·필터·월 변경 시 무효화합니다.
- 같은 서버 revision이면 캐시 파일과 달력을 갱신하지 않습니다. 상태 알림만 바뀌었다고 화면을 다시 그리지 않습니다.
- 연속 입력은 첫 입력 후 16ms에 묶어 처리합니다. 마우스 이동 때마다 타이머를 뒤로 미루지 않습니다.

## 비교 결과

| 시험 | 2.1.0 | 2.2 개선 소스 |
|---|---:|---:|
| 날짜 hover 84회, 총 경과 시간 | 3,760ms | 534ms |
| 같은 시험의 앱 CPU 시간 | 2,109ms | 78ms |
| 같은 시험 중 누적 관리 힙 할당 | 1,031,061,584 bytes | 131,072 bytes |
| 같은 시험의 Gen 2 GC 횟수 | 28회 | 0회 |
| 같은 시험 직후 앱 작업집합 | 98.2MiB | 74.5MiB |
| 창 이동 24회, 총 경과 시간 | 914ms | 491ms |
| 일반 월 변경 6회 | 214ms | 188ms |
| 학교 일정 5,000개에서 월 변경 6회 | 311ms | 245ms |

날짜 hover 시험의 총 경과 시간은 약 **7배** 빨라졌습니다. 누적 할당은 **99.9% 이상** 감소했습니다. 누적 할당은 시험 중 만들었다가 버린 객체 총량으로, 동시에 RAM 1GB를 차지했다는 의미가 아닙니다. CPU 시간은 앱 프로세스가 사용한 누적 시간이고 전체 컴퓨터의 사용률(%)과 다릅니다.

측정은 한 PC에서 얻은 값이며 백그라운드 작업·Windows·화면 크기·아이콘 수·데이터 양에 따라 달라집니다. 실행 중 작업집합은 OS와 GC에 따라 변동합니다. PC 전체 사용량이나 GPU 메모리 전체를 측정한 결과는 아닙니다.

## 재현

Visual Studio 2022 Build Tools와 .NET Framework 개발 컴파일러가 필요합니다. 실제 Explorer에 합성하므로 전용 테스트 PC/세션에서 진행하세요. 이미 실행 중인 달력을 종료하고 저장소의 태그를 받아 둡니다.

```powershell
git fetch --tags origin
cd widget
.\analysis\Run-PerformanceProbe.ps1 -BaselineRef v2.1.0
```

스크립트는 지정한 Git 버전의 소스와 현재 소스로 DLL과 검사 프로그램을 각각 만듭니다. 4회 hover 예열 후 동일한 입력을 순서대로 수행하고 `analysis/performance/baseline.json`, `optimized.json`에 결과를 씁니다. 시험 단계 전 GC를 실행하며 `AppDomain.MonitoringTotalAllocatedMemorySize`, 프로세스 CPU 시간, Stopwatch를 사용합니다. 테스트 데이터는 별도 fixture 파일을 사용합니다.

## 정확성·회귀 검사

`NativeSmoke.cs`에서 다음 항목을 검사했습니다.

- 부분 hover 갱신 결과와 새로 그린 전체 프레임이 픽셀 단위로 일치.
- 공유 메모리에 반영된 전체 픽셀도 앱 프레임과 일치.
- hover가 전체 프레임을 전송하지 않으며, 이동은 픽셀을 전송하지 않음.
- 누락된 sequence는 전체 복사로 복구.
- 월간 캐시와 기존 날짜별 조회가 42일·모든 학년 필터에서 일치.
- 숨김 중 갱신 억제와 재표시 시 최신 데이터 반영.
- 네이티브 메모 입력·저장·취소, 할 일 완료·취소, 투명도, 이동·크기 조절, DPI, 일반 창/바탕화면 전환.
- 유휴 중 불필요한 프레임 전송 없음.

`FeedSmoke.cs`에서는 같은 revision 응답이 캐시를 다시 쓰거나 데이터 변경 이벤트를 발생시키지 않는지, 수정·삭제·오프라인 캐시·읽기 토큰이 유지되는지 확인했습니다. 최신 설치본의 설치·실행 중 업데이트·제거도 별도로 검사합니다.

참고: [CreateFileMapping의 SEC_RESERVE](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-createfilemappinga), [VirtualAlloc](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualalloc).
